# Limerick Council Meetings

[Visit the searchable archive](https://farronf.github.io/limerick-council-meetings/)

This repository contains texts extracted all publicly available meeting agendas and minutes from Limerick City and County Council. These are generated by PDFs that are uploaded to https://www.limerick.ie/council/your-council/meetings

The purpose of this repo is to allow easy searching of the contents of these PDFs by utilizing github's built in search functionality. It also may be easier to navigate to meetings on specific dates as the limerick.ie website only supports navigation one month at a time.

## Why?

Transparency in local government is essential to a healthy democracy. While official minutes are available, they can be difficult to find, navigate, and search through. This project aims to make these records more accessible, searchable, and user-friendly — helping to bridge the gap between the council's decisions and the community it serves.

## Notes

Scanned pages are read using basic OCR and as such the contents are likely to be inaccurate. These pages have a disclaimer at the top in the markdown.

Files are located in the meeting as they are uploaded to limerick.ie as such minutes will be associated with the meeting where they were adopted rather than the meeting they were recorded.

When searching across in a year folder minutes for meetings near the end of the year are likely to be adopted at the next relevant meeting in the year after.

Images in PDFs are currently omitted to ensure searching is easier. They will be marked with (Image omitted). To view these images you will need to navigate to the meeting

## Search Tips

Note: It is no longer intended that this repo be searched directly. Please [visit the searchable archive instead](https://farronf.github.io/limerick-council-meetings/)

The following notes are being preserved for users who wish to search with github. But this may yield unexpected results.

You must have a GitHub account and be signed in to use GitHub's search feature

Include `path:docs/meetings` in every GitHub search to limit results to meeting records. For example:

`bus lane path:docs/meetings`

`"bus lane" path:docs/meetings`

![example](https://i.imgur.com/7GIuqQF.png)

From here you will see matching meeting documents.

You can further refine the search into relevant paths by clicking one of the "Paths" shown above on the left.

Searching multiple words will only show files where all those words are present anywhere in the file.

If you want to search a specific phrase you should wrap it in quotation marks. For example, `"bus lane"` matches those words together, while `bus lane` matches documents containing both words even if they appear separately.

### Useful additional parameters

Additional parameters can be included in a search

#### Search a year/month:

To search only files from meetings in 2024, combine the year path with the meeting directory:

`path:docs/meetings/2024`

This is very effective for agendas however remember that minutes are stored in the meeting they are adopted, not the meeting they were recorded in. As such minutes for meetings at the end of the year are likely to be stored in the following year.

It may be more effective to search for year anywhere in the path but this may give results from a slightly larger range.

`path:docs/meetings/**/*2024*`

To search only files from meetings in September 2023

`path:docs/meetings/2023/09`

#### Searching a specific districts meetings

Use one of the following to limit searches to a specific council body. The `docs/meetings` prefix excludes the README, source files, and other non-meeting content.

`path:docs/meetings/**/*Limerick City and County*`

`path:docs/meetings/**/*Metropolitan*`

`path:docs/meetings/**/*Cappamore-Kilmallock*`

`path:docs/meetings/**/*Adare-Rathkeale*`

`path:docs/meetings/**/*Newcastle West*`

#### Case sensitive

Add the following to make searches case sensitive

`case:true`

## Updating the archive

The workflow is controlled from `src/tools/main.py` and organized into
`download`, `process`, `publish`, and `shared` modules. It fetches public
meeting pages from limerick.ie, downloads PDFs, extracts their text into a
separate processed folder, then publishes the processed meetings to the
searchable archive by default.

### Run with Docker

Install [Docker Desktop](https://www.docker.com/products/docker-desktop/), then
run these commands from the repository root to build the image and run the
complete workflow for the default date range:

```bash
docker compose build
docker compose run --rm tools
```

The default range starts in January 2014 and ends in the current month. By
default, the tool downloads files whose names contain "agenda" or "minutes",
processes the downloaded PDFs into Markdown, and publishes the processed
meetings. A `meeting_details.json` file is also saved for each downloaded
meeting with meeting details and download status.

To process a smaller date range or filter meetings and documents, pass options
after `tools`:

```bash
docker compose run --rm tools --start-year 2025 --start-month 1 --end-year 2025 --end-month 3
docker compose run --rm tools --start-year 2025 --end-year 2025 --meeting-filter "council budget" --file-filter agenda
```

Available options:

- `--start-year` (default: `2014`) and `--start-month` (default: `1`) set the
  start of the date range.
- `--end-year` and `--end-month` (default: current year and month) set its end.
- `--meeting-filter WORD [WORD ...]` includes meetings whose names contain any
  of the given words, case-insensitively.
- `--file-filter WORD [WORD ...]` includes documents whose displayed link text
  contains any of the given words, case-insensitively. The default is
  `agenda minutes`; pass `--file-filter` with no values to include all files.
- `--download-location` sets where source PDFs and meeting metadata are saved
  (default: `./data/downloaded`).
- `--output-location` sets where generated Markdown is saved (default:
  `./data/processed`).
- `--logs-location` sets where logs are saved (default: `./.logs`).
- `--dont-download` processes files already in the download location without
  fetching new ones.
- `--dont-process` downloads source files without converting PDFs to Markdown.
- `--dont-publish` leaves processed Markdown in `data/processed/` without
  copying it to the published archive, so you can review it before publishing.
- Existing PDFs and generated Markdown are skipped by default, so repeated runs
  can pick up missing work without downloading or converting everything again.
- `--redownload-existing` downloads matching PDFs again even when the local file
  already exists.
- `--reprocess-existing` regenerates Markdown even when the processed output
  already exists.
- `--republish-existing` overwrites files already in the published archive with
  files from the processed output and reruns publishing post-processing. Combine
  it with `--reprocess-existing` to regenerate Markdown from the downloaded
  PDFs before publishing. With `--dont-process`, it republishes existing
  processed meeting folders in the selected date range (and optional meeting
  filter) without reading downloads or regenerating Markdown.
- `--delete-downloads-after-complete` removes the entire download location
  after the run; use with care if it contains files you want to keep.

Docker Compose persists downloads in `data/downloaded/`, processed Markdown in
`data/processed/`, and logs in `.logs/` on the host. Generated archive files
are written to `docs/meetings/`. Review the changes under `docs/meetings/`
before committing. Publishing normalizes meeting headings, regenerates archive
navigation READMEs, marks PDF page boundaries for Pagefind to ignore, and adds
Pagefind metadata. These post-processing scripts run across the existing
archive when new files are published. Files already present in the published
archive are skipped during copying, even if their content differs; only missing
files are copied from the processed output. Post-processing still normalizes
the archive when new files are published. Unrelated archive files are not
deleted. Tagging errors are written to `tagging_errors.log` in the configured
logs directory. Meeting folders use the format `DD @ HH-MM - Meeting Name` so
meetings with the same title on the same day remain separate and sort by time.
Use `--dont-publish` when you want to inspect or adjust processed output before
publishing it.

Only files in `docs/` are included in the searchable site. Build locally with
`mkdocs build`; the repository's GitHub Pages workflow builds and publishes
the site on pushes to `main`.

### Run locally

For development without Docker, install Python 3.12 or later and create a
virtual environment from the repository root:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

On macOS or Linux, activate it with `source .venv/bin/activate` instead.
Install both the tools and site dependencies into this virtual environment,
then set `PYTHONPATH` and run the tool:

```powershell
python -m pip install -r requirements.txt
$env:PYTHONPATH = "src"
python -m tools --help
python -m tools --start-year 2025 --start-month 1 --end-year 2025 --end-month 3
```

On macOS or Linux, set the path with `export PYTHONPATH=src` before running the
tool. `requirements.txt` includes both `requirements-tools.txt` and
`requirements-site.txt`, so the same virtual environment can run the tools and
build the MkDocs site. The tool uses the same defaults and options as the
Docker run. Install Tesseract separately on the host and make sure it is
available on `PATH` for OCR of scanned PDFs.
